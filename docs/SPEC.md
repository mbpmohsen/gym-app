# gym-app — مشخصات (Spec v1)

نرم‌افزار متن‌باز مدیریت باشگاه: محلی، آفلاین، رایگان، با حضور و غیاب خودکار از طریق تشخیص چهره با وبکم.

این سند مرجع تصمیم‌هاست. هر تصمیم جدید اول اینجا ثبت می‌شه، بعد پیاده‌سازی.

---

## ۱. دامنه

**هست:**
- اعضا با ثبت چهره
- تعرفه‌ها و اشتراک‌ها (جلسه‌ای، زمانی، ترکیبی) با تواتر، دوش و کمد
- پرداخت و بدهی (پرداخت ناقص)
- ورود و خروج خودکار با دوربین، به‌علاوه‌ی ورود دستی برای مواقع اضطراری
- سانس‌های زنانه و مردانه
- اعلام صوتی (صدای مرد یا زن، قابل تنظیم)
- گزارش‌ها با فیلتر دقیق و خروجی اکسل، داشبورد

**نیست (عمداً):**
- قسط، فریز، برگشت پول، رسید، پرونده‌ی پزشکی
- نقش‌های مختلف کاربر (فقط مدیر)
- چند سیستم یا شبکه (فقط یک کامپیوتر)
- ارسال پیامک (فقط خروجی اکسل برای سامانه‌ی پیامک)
- کنترل گیت یا قفل

## ۲. معماری

```
┌──────────── کامپیوتر پذیرش ─────────────────────────────────────┐
│                                                                │
│  وبکم ──► face-service (Rust)  127.0.0.1:7480                   │
│              │ SSE: recognized / unknown / uncertain           │
│              ▼                                                 │
│           gym-server (Rust, axum, SQLite)  127.0.0.1:7470      │
│              │ قواعد ورود/خروج، اشتراک، گزارش، اکسل               │
│              │ SSE به UI                                       │
│              ▼                                                 │
│           مرورگر: UI (React + TS)  ──► اسپیکر (پخش صدا)          │
└────────────────────────────────────────────────────────────────┘
```

| تصمیم | دلیل |
|---|---|
| بک‌اند Rust (axum + SQLite) | سبک روی کامپیوترهای ضعیف؛ همون استک face-service |
| فرانت React + TypeScript (Vite) + **shadcn/ui** (Radix، Tailwind v4)، build داخل exe سرور embed می‌شه | یک فایل اجرایی، بدون نصب Node |
| تم: حالت (روشن / تیره / سیستم) × ۶ رنگ اصلی؛ رنگ‌های وضعیت (سبز، زرد، قرمز) در همه‌ی تم‌ها ثابت | انتخاب کاربر؛ معنی رنگ‌ها در صفحه‌ی پذیرش نباید با تم عوض بشه |
| هر دو سرویس Windows Service، فقط روی 127.0.0.1 | آفلاین، از شبکه در دسترس نیست |
| **صدا رو مرورگر پخش می‌کنه، نه سرور** | Windows Service در Session 0 اجرا می‌شه و پخش صدا ازش قابل اعتماد نیست. صفحه‌ی پذیرش همیشه بازه. مرورگر قبل از اولین کلیک اجازه‌ی پخش خودکار نمی‌ده، پس ورود با رمز این کلیک رو فراهم می‌کنه |
| پخش با **Web Audio API** (یک `AudioContext` که با کلیک ورود فعال می‌شه)، نه تگ `<audio>` | در spike، تگ `<audio>` حتی با تب visible گاهی با `NotAllowedError` رد شد؛ Web Audio ۱۰ از ۱۰ پخش کرد |
| منطق ورود و خروج در gym-server ـه، نه face-service | face-service فقط می‌گه «این آدم بود» |
| **cooldown در face-service = ۶۰ ثانیه** (نه ۶۰۰) | با ۶۰۰، خروجی که بین ۵ تا ۱۰ دقیقه بعد از ورود باشه دیده نمی‌شد. قاعده‌ی ۵ دقیقه رو gym-server اعمال می‌کنه |
| تاریخ در DB میلادی (ISO)، در UI و اکسل شمسی | محاسبه‌ی ساده و درست؛ نمایش برای کاربر ایرانی |
| مبلغ‌ها به **تومان** و عدد صحیح | بدون خطای اعشار |

## ۴. قواعد کسب‌وکار

### ۴.۱ اعتبار اشتراک (در تاریخ D)
| نوع | معتبره اگه |
|---|---|
| `sessions` | `sessions_used < sessions` (بدون تاریخ انقضا) |
| `duration` | `start_date ≤ D ≤ end_date` |
| `combined` | هر دو شرط بالا |

اشتراکی که `start_date` اون آینده‌ست (پیش‌خرید) هنوز معتبر نیست.

### ۴.۲ وضعیت شهریه‌ی عضو
- `none`: هیچ‌وقت اشتراک نداشته
- `expired`: هیچ اشتراک معتبری نداره
- `debt`: اشتراک معتبر داره، ولی جمع بدهی همه‌ی اشتراک‌هاش > ۰ ـه
- `ok`: اشتراک معتبر داره و بدهی نداره

`expired`، `debt` و `none` صدای **«پایان شهریه»** رو پخش می‌کنن و در لیست قرمز نشون داده می‌شن.

### ۴.۳ ورود و خروج (state machine)

ورودی: رویداد `recognized(member_id)` از face-service، یا ورود دستی.

```
عضو داخل نیست (visit باز نداره):
  → ورود جدید
      صدا: «خوش آمدید» یا «پایان شهریه»
      کسر جلسه (۴.۴)
      علامت‌ها (۴.۵)

عضو داخله و از entered_at کمتر از exit_min_minutes (۵ دقیقه) گذشته:
  → هیچ کاری نکن (داره کفش درمیاره)

عضو داخله و ≥ ۵ دقیقه گذشته:
  → خروج (exit_source = camera)
      صدا: «خداحافظ»

عضو داخل نیست، ولی کمتر از ۵ دقیقه پیش (با دوربین یا دستی) خارج شده:
  → هیچ کاری نکن (داره کفش می‌پوشه؛ ورود جدید حساب نمی‌شه)
```

- **خروج خودکار:** هر visit که بیشتر از `auto_exit_hours` (۴ ساعت) باز بمونه، با `exit_source = auto` بسته می‌شه. بدون صدا.
- **ورود بعد از خروج** همیشه ورود جدیده.

### ۴.۴ کسر جلسه
- **حداکثر یک جلسه در هر روز تقویمی** برای هر عضو. ورود دوم در همون روز چیزی کسر نمی‌کنه.
- از کدوم اشتراک: از **قدیمی‌ترین اشتراک معتبر جلسه‌دار** (`sessions` یا `combined`)، به ترتیب `start_date`. اشتراک `duration` جلسه‌ای کسر نمی‌کنه.
- اگه اشتراک معتبر نداره: ورود ثبت می‌شه (`status = expired`)، ولی چیزی کسر نمی‌شه.

### ۴.۵ علامت‌ها و هشدارها (روی هر visit)
| علامت | شرط | نمایش |
|---|---|---|
| `second_visit_today` | ورود دیگه‌ای امروز که حداقل `second_visit_hours` (۳ ساعت) قبل‌تر بوده | برچسب «بار دوم امروز» |
| `alternate_day` | اشتراکی که ازش کسر شد `alternate` ـه و دیروز هم ورود کسرکننده داشته | هشدار زرد |
| `wrong_shift` | جنسیت عضو با سانس فعلی جور نیست | **هشدار قرمز + صدای «سانس نامعتبر»** |
| `outside_shift` | الان هیچ سانسی تعریف نشده | هشدار زرد |

**اولویت صدا** وقتی چند حالت همزمان پیش میاد: سانس اشتباه ← پایان شهریه ← خوش آمدید. فقط یک صدا پخش می‌شه.

فایل‌های صوتی: `assets/voices/{male,female}/{welcome,goodbye,end-of-tuition,wrong-shift}.mp3`

### ۴.۶ رویدادهای ناشناس و نامطمئن
- `uncertain`: در لیست پذیرش با عکس و کاندیداها نشون داده می‌شه. مدیر با یه کلیک انتخاب می‌کنه، و ورود با `entry_source = picked` ثبت می‌شه.
- `unknown`: با عکس در لیست نشون داده می‌شه (بی‌صدا). مدیر می‌تونه رد کنه، یا یه عضو رو انتخاب کنه.

### ۴.۷ ورود و خروج دستی
از صفحه‌ی پذیرش یا پروفایل عضو. همون قواعد ۴.۳ تا ۴.۵ اعمال می‌شه، به‌جز قاعده‌ی ۵ دقیقه.

**حذف ورود اشتباه:** فقط برای ورودهای امروز. visit پاک می‌شه و جلسه‌ی کسرشده به اشتراک برمی‌گرده (برای وقتی که کاندیدای اشتباه انتخاب شده).

**عکس‌ها:** face-service فقط ۲۰۰۰ رویداد آخر رو نگه می‌داره؛ gym-server عکس هر ورود و هر ناشناس رو در `data/snapshots` کپی می‌کنه و بعد از ۹۰ روز پاک می‌کنه.

**رویدادهای قدیمی:** اگه gym-server مدتی خاموش بوده، رویدادهای جامانده با `Last-Event-ID` با زمان واقعی خودشون ثبت می‌شن، ولی صدایی پخش نمی‌شه (فقط رویدادهای کمتر از ۶۰ ثانیه صدا دارن).

**دوربین فقط وقتی برنامه باز است:** gym-server تعداد پنجره‌های باز برنامه را می‌شمارد (اتصال‌های `/api/live`). تا وقتی حداقل یکی باز است دوربین روشن است؛ ۲ دقیقه بعد از بسته شدن آخرین پنجره، دوربین آزاد می‌شود (چراغش خاموش) و با باز شدن دوباره‌ی برنامه روشن می‌شود (`POST /v1/camera` در face-service). در این فاصله ورود و خروجی ثبت نمی‌شود.

**یک زبانه:** اگه برنامه در چند زبانه باز باشه، فقط یکی صدا پخش می‌کنه (Web Locks).

### ۴.۸ اشتراک جدید
- مبلغ پیش‌فرض = قیمت تعرفه. قابل ویرایش.
- مبلغ پرداختی موقع ثبت می‌تونه کمتر از مبلغ اشتراک باشه؛ بقیه بدهی می‌شه و بعداً با «ثبت پرداخت» تسویه می‌شه.
- `start_date` پیش‌فرض: **امروز**، یا اگه اشتراک زمانیِ معتبری از همین نوع داره، **روز بعد از پایانش**. قابل ویرایش.

### ۴.۹ عضو بایگانی‌شده
از face-service حذف می‌شه، پس دیگه شناخته نمی‌شه. سابقه‌اش برای گزارش‌ها باقی می‌مونه.

### ۴.۱۰ همگام‌سازی با face-service
موقع استارت و هر ۱۰ دقیقه، `GET /v1/gallery` با لیست `members` مقایسه می‌شه:
- چهره‌ای که عضوش وجود نداره یا بایگانی شده ← حذف از face-service
- عضوی که `face_enrolled = true` ـه ولی در face-service نیست ← `face_enrolled = false` و هشدار در داشبورد

| **گزارش‌ها** | بخش ۶ |

| **تنظیمات** | اسم باشگاه، صدای مرد یا زن (با دکمه‌ی پخش آزمایشی)، پارامترهای بخش ۳، رمز، وضعیت face-service، آستانه‌ی تشخیص |

## ۶. گزارش‌ها و داشبورد

همه‌ی گزارش‌ها **فیلتر بازه‌ی تاریخ شمسی** و **خروجی اکسل** دارن. اکسل همون ستون‌ها و فیلترهایی رو داره که روی صفحه دیده می‌شه.

| گزارش | ستون‌ها | فیلترها |
|---|---|---|
| **درآمد** | تاریخ، عضو، تعرفه، مبلغ اشتراک، پرداختی | بازه، تعرفه، نوع، جنسیت؛ جمع کل؛ گروه‌بندی روزانه، هفتگی یا ماهانه |
| **در حال اتمام** | عضو، موبایل، تعرفه، جلسات باقی‌مونده، روزهای باقی‌مونده | «≤ N جلسه» یا «≤ N روز»، جنسیت، تعرفه |
| **تمام‌شده‌ها** | عضو، موبایل، تاریخ اتمام، آخرین ورود | بازه‌ی اتمام، «از اتمام بیش از N روز گذشته» |
| **بدهکاران** | عضو، موبایل، اشتراک، مبلغ، پرداختی، بدهی | حداقل بدهی |
| **ورودها** (پیش‌فرض: امروز) | عضو، ورود، خروج، مدت حضور، وضعیت، برچسب‌ها، منبع | بازه، جنسیت، وضعیت، برچسب، منبع |

| **خروجی پیامک** | اسم، موبایل (و ستون‌های انتخابی) | هر کدوم از لیست‌های بالا ← «خروجی برای پیامک» |

**داشبورد:**
- کارت‌ها: الان داخل، ورودهای امروز، درآمد امروز و این ماه، اعضای فعال، در حال اتمام این هفته، بدهی کل
- نمودارها: درآمد ۳۰ روز اخیر، ورود روزانه‌ی ۳۰ روز اخیر، heatmap شلوغی
- هشدارها: face-service قطعه، دوربین قطعه، عضوهای بدون چهره
